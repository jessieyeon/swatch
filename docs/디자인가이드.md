# 디자인 가이드 — 스와치 v2

- 요소 번호는 코드 주석(`// S1-3` 등) · 발표자료 부록 B5-4 · 화면 캡처의 번호와 같다.
- 위젯 이름은 GAI3008-01 5주차 「Flutter 위젯 치트시트 v1.0.0」의 이름을 그대로 쓴다. ErrorView · EmptyView는 `lib/widgets.dart`에 만든 화면 조각이다.
- 원칙 번호 P01–P10은 닐슨 10원칙 번호와 같다.
  P01 시스템 상태의 가시성 · P02 현실 세계와의 일치 · P03 사용자 통제와 자유 · P04 일관성과 표준 · P05 오류 예방 · P06 기억보다 인식 · P07 유연성과 효율성 · P08 미학적이고 미니멀한 디자인 · P09 오류를 알아보고 진단하고 복구하도록 돕기 · P10 도움말과 문서
- 배경은 흰색으로 통일한다(화면 · 제목 줄 · 탭 · 아래 시트 · 대화상자 · 카드). 레퍼런스 이미지의 색이 배경 색에 섞이지 않고 그대로 보이게 하기 위해서다(P08). 검색창과 이미지가 없는 자리만 연한 회색으로 구분한다.
- 상태관리 포인트는 **표시만** 한다. 지금은 화면 안 표시를 바꾸는 `setState`만 쓰고, 코드에는 `// STATE:` 주석으로 남긴다(13주차 상태관리에서 구현).
- 이 가이드는 발표자료 부록 B5-4(화면별 요소 분석표)의 요약본이다. 코드의 화면 파일 맨 위 대응표와 번호 · 명칭이 같다. 이 가이드에 없는 화면은 만들지 않는다.

## 4. 디자인 가이드 글 (위에서 정의한 명칭을 그대로 쓴다)

### S-1 보관함 (홈 · 탭)

‘보관함’은 내가 저장한 레퍼런스만 모아 보는 첫 화면이다. Pinterest에서 내 보드에 추천과 광고가 끼어들던 문제(리뷰 #3)를 없애기 위해, 보관함에는 추천 · 광고를 하나도 넣지 않는다(P08). ‘레퍼런스 카드’는 사진만 보여 줘서 모은 레퍼런스를 빠르게 훑어보게 한다(P08). 처음 기획에서는 카드에 저장 이유를 함께 넣었지만, 보관함은 사진으로 훑어보는 곳이고 이유는 상세(S-2)와 검색 결과(S-6)에서 읽는 것으로 바꿨다(셀프 논증 쟁점 5). 위쪽 ‘보관함 검색’과 ‘태그 칩’은 쌓인 레퍼런스를 이유와 태그로 다시 찾는 입구다. 카드를 길게 누르면 ‘선택 모드’가 되고, ‘정리 액션바’로 여러 개를 한 번에 보드로 옮기거나 지운다(P07). 지우기 전에는 ‘삭제 확인’으로 한 번 더 묻는다(P05). 결과는 SnackBar로만 보여 주고 실제로 저장하거나 지우지 않는다.

### S-2 레퍼런스 상세 (쌓기 · 넓은 화면은 S-1 오른쪽 2단)

‘레퍼런스 상세’는 레퍼런스 하나를 크게 보고 저장 이유를 읽는 화면이다. 정보 전달 순서는 이미지 → 제목 → ‘저장 이유’ → 태그 → 출처 · 저장한 날이다. ‘저장 이유’는 강조 배경의 카드로 두어 이미지 다음으로 가장 먼저 읽히게 한다(P06). 이것이 Pinterest 리뷰 #1(“이 사진의 어떤 점이 좋았는지 사진마다 구체적으로 메모를 하고 싶습니다.”)에 대한 v2의 답이다. 넓은 화면에서는 새 화면으로 넘어가지 않고 보관함 오른쪽에 같은 내용을 띄운다.

### S-3 저장 시트 (덮기)

‘저장 시트’는 레퍼런스를 저장하면서 유형 · ‘저장 이유’ · 태그 · 보드를 함께 남기는 아래 패널이다. 태그와 보드는 고르기만 하는 게 아니라 ‘+ 새 태그’ · ‘+ 새 보드’로 그 자리에서 만들 수 있다(화면에만 보이고 저장하지 않음, 셀프 논증 쟁점 6). ‘유형’은 AI가 이미지 유형(포스터 · PPT · 타이포그래피 등)을 추천하고 사용자가 눌러서 확정하거나 고친다. 분류 수고를 덜어 나중에 다시 찾기를 돕고, 유형을 알면 이유(PPT는 폰트 계층, 포스터는 색감처럼)도 떠올리기 쉬워진다. 데모에서는 실제 분석 없이 db.json에 미리 써 둔 가짜 추천(GET /aiTypeSuggestions)을 보여 준다(셀프 논증 쟁점 4). 피쉬본의 근본 원인(저장 순간에 ‘왜 좋은지’를 기록하는 구조가 없다)을 고치는 핵심 요소다(P06). 이유 칸에는 예시 문장과 ‘나중에 이 문장으로 다시 찾을 수 있어요’ 도움말을 둬서 왜 써야 하는지 알게 한다. 보드는 최근 몇 개가 아니라 전체 목록에서 고른다. 저장 버튼은 실제로 저장하지 않고 SnackBar로 결과만 보여 준다.

### S-4 보드 목록 (탭)

‘보드’는 프로젝트별로 레퍼런스를 묶는 모음이다. ‘보드 카드’는 커버 이미지와 이름, 한 줄 설명을 보여 줘서 어떤 프로젝트의 모음인지 바로 알 수 있게 한다(P06). 카드를 누르면 S-5 보드 상세로 쌓여 들어간다. 오른쪽 아래 ‘+ 새 보드’로 보드를 직접 만들 수 있다. 저장 시트의 ‘+ 새 보드’(쟁점 6)와 같은 생각이며, 만든 보드는 화면에만 보이고 저장하지 않는다.

### S-5 보드 상세 (쌓기)

‘보드 상세’는 한 보드에 묶인 레퍼런스만 보는 화면이다. 레퍼런스 카드는 보관함과 똑같이 그려 어디서 보든 같은 방식으로 읽히게 한다(P04). 보드가 비어 있으면 오류처럼 보이지 않도록 ‘비어 있어요’라고 말하고, 보관함에서 길게 눌러 옮기거나 새로 저장하는 방법을 함께 알려 준다(P01 · P09).

### S-6 검색 결과 (쌓기)

‘검색 결과’는 보관함 검색에서 넘어오는 화면으로, 제목 · 저장 이유 · 태그에서 찾은 레퍼런스를 보여 준다. 결과마다 저장 이유 문장을 함께 보여 줘서 왜 이 결과가 나왔는지 알 수 있게 한다(P06). 결과가 없을 때는 Pinterest처럼 ‘찾을 수 없음’에서 멈추지 않고, 태그를 대안 검색어로 보여 줘 바로 다시 찾게 한다(P09 · 저니 하락 ①). 검색은 앱이 아니라 json-server의 `?q=` 조회로 처리한다.
